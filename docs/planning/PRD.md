# Family Health OS (FHOS) — Product Requirements Document
> Phase 1 MVP | Version 1.0.0 | 2026-04-19

---

## 1. 제품 개요

### 1.1 목적
가족을 하나의 건강 운영 단위로 연결하여 AI 기반 공동 챌린지를 수행하고, 룰 기반 리스크 점수로 가족 건강을 시각화하는 예방 헬스케어 MVP.

### 1.2 핵심 검증 목표
> **"가족 단위 행동 변화 가능성 확인"** — 완전 무료, PMF 검증 도구

### 1.3 성공 지표
| 지표 | 목표 |
|------|------|
| 온보딩 완료 시간 | 3분 이내 |
| D1 리텐션 | 50% 이상 |
| 가족 그룹 초대 성공률 | 측정 후 기준선 수립 |
| 챌린지 완료율 | 측정 후 기준선 수립 |
| 앱 크래시율 | 0% (핵심 플로우) |

---

## 2. 사용자 및 이해관계자

### 2.1 타깃 사용자
- **주 사용자**: 건강 관리에 관심 있는 가족 단위 (2인 이상)
- **미성년자**: 독립 소셜 로그인 허용, 부모 PIPA 동의 플로우 필수
- **플랫폼**: iOS + Android

### 2.2 사용자 역할
| 역할 | 설명 |
|------|------|
| self | 본인 |
| parent | 부모 |
| spouse | 배우자 |
| child | 자녀 (미성년자 포함) |

## 3. 기능 요구사항

### 3.1 온보딩 및 가족 그룹 (AC-01, AC-08)

#### 3.1.1 소셜 로그인
- 카카오 소셜 로그인 (단일 제공자)
- 미성년자도 독립 소셜 로그인 허용 (카카오 14세 미만 제한 정책 — 해당 연령은 보호자 계정으로 가족 그룹 초대)

#### 3.1.2 가족 그룹 생성 및 초대
- 최소 2명 이상으로 구성된 가족 그룹 생성
- 초대 링크 / 코드 기반 구성원 초대
- 구성원 간 데이터 공유는 동의 기반

#### 3.1.3 미성년자 PIPA 동의 플로우
- 미성년자 가입 시 부모 동의 화면 노출
- 부모 동의 저장 및 `pipa_consent_by` 기록
- 동의 없이 미성년자 데이터 처리 불가

#### 3.1.4 건강 설문 (온보딩)
- 항목: 신체 정보, 현재 질환, 복약 여부, 가족력, 생활습관
- 재설문 대상: 변화 가능 항목만 (가족력 제외)
- 미응답 시 기존 데이터 유지

### 3.2 리스크 점수 (AC-02)

#### 3.2.1 룰 기반 점수 계산
```
총점 = 유전(30%) + 생활습관(25%) + 행동(20%) + 환경(15%) + 임상(10%)
```

| 요소 | 가중치 | 입력 데이터 |
|------|--------|------------|
| 유전 (genetic) | 30% | 가족력 (당뇨, 고혈압, 심혈관, 비만) |
| 생활습관 (lifestyle) | 25% | 흡연, 음주, 식습관, 활동 수준 |
| 행동 (behavior) | 20% | 챌린지 참여율, 달성 이력 |
| 환경 (environment) | 15% | 수면 패턴 (취침/기상 시간) |
| 임상 (clinical) | 10% | BMI, 기존 질환 |

#### 3.2.2 점수 갱신 트리거
- 설문 재응답 시
- 웨어러블 데이터 동기화 시
- 챌린지 완료 시 (행동 점수)

#### 3.2.3 점수 표시
- 홈 화면 최우선 렌더링
- 가족 평균 점수 + 개인별 점수 제공
- LLM 사용 금지 (룰 기반만 사용)

### 3.3 AI 챌린지 추천 (AC-03)

#### 3.3.1 입력
- 가족 리스크 점수
- 챌린지 달성 이력
- 카테고리 선호도

#### 3.3.2 출력
- 가드레일 통과 챌린지 1개 이상 제안
- 카테고리: walking, diet, sleep, exercise, hydration

#### 3.3.3 LLM 가드레일
- **허용 카테고리 사전 정의(A안)**: walking, diet, sleep, exercise, hydration 만 허용
- **금지 목록(B안)**: 의료 진단, 약물 추천 등 명시적 금지어 필터
- A안 + B안 복합 적용

#### 3.3.4 면책 문구
모든 AI 추천 챌린지에 면책 문구 필수 표시:
> "이 서비스는 의료 진단이 아닌 건강 관리 서비스입니다."

### 3.4 챌린지 체크인 (AC-04)

#### 3.4.1 완료 판정 우선순위
1. 웨어러블 데이터 (Google Health Connect / Apple HealthKit)
2. 수동 입력
3. 사진 업로드 (업로드 자체가 완료 조건)

#### 3.4.2 웨어러블 연동
- Android: Google Health Connect
- iOS: Apple HealthKit
- 동기화 실패 시 이전 데이터 유지 (AC-09)
- 권한 거부 상태에서도 이전 데이터 노출

### 3.5 마감 및 알림 (AC-05)
- 가족 공동 마감 시간 설정
- 마감 2시간 전 푸시 알림 발송
- 마감 시간은 가족 합의로 설정

### 3.6 스트리크 및 랭킹 (AC-06)
- **스트리크**: 가족 단위 연속 챌린지 성공 일수 카운트
- **랭킹**: 리스크 개선율 기준 정렬 (점수 하락 = 건강 개선)

### 3.7 배지 시스템 (AC-07)
| 배지 | 조건 |
|------|------|
| first_challenge | 첫 챌린지 완료 |
| streak_7 | 7일 연속 스트리크 |
| streak_30 | 30일 연속 스트리크 |
| risk_improved | 리스크 점수 개선 |
| family_complete | 가족 전원 챌린지 완료 |

- 하드코딩 방식 (Phase 1)
- 개인 배지 + 가족 배지 구분

### 3.8 데이터 정책 (AC-10)
- **가족 구성원 제외**: 해당 구성원 데이터 즉시 삭제
- **계정 탈퇴**: 90일 후 자동 파기
- PIPA 준수 필수

## 4. 비기능 요구사항

### 4.1 성능
- 온보딩 ~ 첫 챌린지 완료 플로우: 크래시 없음
- 리스크 점수 계산: 서버 응답 3초 이내
- 푸시 알림 발송 지연: 마감 2시간 전 ± 5분

### 4.2 보안
- PIPA(개인정보보호법) 완전 준수
- 가족 구성원 간 데이터 공유: 명시적 동의 필수
- 건강 데이터 암호화 저장
- JWT 기반 인증

### 4.3 가용성
- 외부 서비스(웨어러블, LLM) 없이도 핵심 기능 동작 (오픈 베타 조기 종료 대비)
- 오프라인 시 이전 데이터 유지

### 4.4 인프라
- AWS, 월 예산 50만원 이하
